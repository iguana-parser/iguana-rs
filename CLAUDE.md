# Project

Language tooling for iguana. 

## Crates

`lsp`: language intelligence for iggy grammars
`terrarium`: Tauri-based grammar debugging tool

Depends on `iguana-rs` at `../iguana-rs` for the parser generator, runtime, and bootstrapped iggy parser.

# Build & Test

## LSP
- `cargo test -p lsp` — run LSP tests
- `cargo check -p lsp` — check LSP compilation

## Terrarium
- `cd terrarium && npm install && npm run tauri dev` — run in dev mode
- `cd terrarium/src-tauri && cargo check` — check Rust backend (separate workspace, not in root)
- `terrarium/src/bindings.ts` is auto-generated by specta from Rust types on app start (debug builds only). Don't edit it manually.

# Terrarium

## Architecture

Tauri 2 app: Rust backend + Svelte 5 frontend. Monaco Editor for grammar editing, Cytoscape.js for graph visualization.

Terrarium runs generated parsers as subprocesses, not as library calls. The parser binary is built via `cargo build --release` in the user's grammar directory. Communication happens via CLI flags (`--write-sppf`, `--write-gss`, `--write-parse-tree`, `--write-timings`, `--list-nonterminals`, etc.) and JSON temp files.

## Modes

- **Design mode**: Grammar editor with Monaco. Calls `lsp` crate directly (not over LSP protocol) for highlighting, formatting, symbols, diagnostics. Always available.
- **Parse mode**: Runs the generated parser on input text. Shows parse tree, SPPF, GSS, and stats. Requires a successful build.
- **Debug mode**: Step-by-step trace replay of parser execution. Requires a build with `--features debug-trace`.

## LSP Integration

Terrarium calls `lsp` functions directly via Tauri commands. Adding a new LSP feature requires three things: a function in `lsp/src/`, a Tauri command wrapper in `terrarium/src-tauri/src/lib.rs`, and a Monaco provider in `MonacoEditor.svelte`.

## UI Changes

UI changes frequently break other parts of the app. When modifying UI code, identify all existing behaviors (class bindings, event handlers, conditional logic) before changing anything. Extend rather than replace.

Shared utilities live in `terrarium/src/lib/` (`graph-styles.ts`, `graph-utils.ts`, `window-utils.ts`, `MonacoEditor.svelte`). Don't duplicate code — extract to `$lib/`.

# LSP Server

`lsp/src/main.rs` + `lsp/src/server.rs` provide a standalone LSP server binary (`iguana-lsp`). Same stateless functions as terrarium, wrapped in LSP protocol handlers. The VS Code extension lives in a separate repo at `../iguana-vscode`.

# Code Style

- Optimize for readability rather than clever tricks
- State what, then why. Not the reverse.
- Use project terminology: "parse tree" not "CST"
- Adverbs before verbs: "directly returns" not "returns directly"
- Don't explain the same thing in two places
- No filler words ("simply," "just," "basically," "naturally," "seamlessly")
- No filler phrases ("it should be noted that," "it is worth mentioning")

# Approach

Don't rush to the first solution. When a change touches shared infrastructure (LSP core, parse result types, spans), explore alternatives before committing to one. However, don't over-engineer: for localized fixes, the straightforward approach is usually right.

# Process

- Keep it conversational. Always discuss what you plan to do if it's complex and don't jump to implementation.
- Follow the instructions very carefully
- Each step should be reviewed before proceeding to the next one

# Tool Use

- Don't write scripts with sed/awk for code refactoring. Only use those tools when you're sure they won't mess things up. Otherwise, fix things manually.
- Start a new conversation before hitting 20% context usage.
