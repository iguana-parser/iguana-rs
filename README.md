# Iguana

A GLL parser generator written in Rust.

## Project Structure

```
iguana-rs/
├── iguana/              # Command-line interface (the `iguana` binary)
├── iguana-compiler/     # Parser generator (grammar IR, analysis, codegen)
├── iguana-runtime/      # Runtime library for generated parsers
├── iggy/                # Generated parser for iggy grammar syntax
├── iguana-lsp/          # Language server for iggy grammars
├── terrarium/           # Grammar debugging tool (Tauri app)
├── web-ui/              # Shared parse-view renderer (npm package)
├── web-viewer/          # Static web viewer for a wasm-compiled parser
├── design-viewer/       # Read-only grammar design view for the website
├── tree-widget/         # Embeddable parse-tree widget for the website docs
├── editors/vscode/      # VS Code extension
└── tests/               # Grammar test crates
```

### Crates

| Crate | Description |
|-------|-------------|
| `iguana` | Command-line interface; builds the `iguana` binary on top of `iguana-compiler`. |
| `iguana-compiler` | Parser generator: grammar IR, analysis, transforms, and code generation. |
| `iguana-runtime` | Runtime library that generated parsers link against. |
| `iggy` | Parser for the iggy grammar syntax, itself generated by iguana. |
| `iguana-lsp` | Language server providing semantic highlighting and diagnostics for `.iggy` files. |
| `terrarium` | Grammar debugging tool (Tauri app, separate workspace at `terrarium/src-tauri`). |

### Web packages

The repository root is also an npm workspace. The `web-ui` package holds the shared TypeScript/Svelte components, and the other packages (and Terrarium) each mount them in a different host, so there is a single renderer to maintain.

| Package | Description |
|---------|-------------|
| `web-ui` | The shared web UI components: the parse-view renderer (a Svelte component with tree, graph, and s-expression views over a parse tree, driven by a pluggable parser backend) and the read-only design view. Terrarium and the other web packages import it. |
| `web-viewer` | A static web app that loads a wasm-compiled parser, parses input in the browser, and mounts the parse view to render the result. No server and no Tauri. |
| `design-viewer` | A static web app that mounts the read-only design view (Monaco with the iggy LSP compiled to wasm) over a grammar. The website's grammar pages embed it. |
| `tree-widget` | An embeddable widget that renders a printed s-expression as an interactive parse-tree graph. The website's docs embed it for parse-tree examples. |

### Dependency Graph

```
iguana-runtime  (standalone, no internal deps)
       ^
     iggy  (depends on runtime)
       ^
 iguana-compiler  (depends on runtime + iggy)
       ^
 iguana / iguana-lsp  (depend on iguana-compiler)
       ^
   terrarium  (depends on runtime + iguana-lsp)
```

On the JavaScript side, `terrarium`, `web-viewer`, `design-viewer`, and `tree-widget` all depend on `web-ui`. `web-viewer` additionally drives a wasm module that `iguana generate --wasm` produces, and `design-viewer` drives the `iguana-lsp` wasm module.

## Building

```bash
cargo build                     # Build all crates
cargo build -p iguana-compiler  # Build just the generator
cargo build -p iguana           # Build the `iguana` CLI binary
```

## CLI

To see all available commands:

```bash
cargo run -p iguana -- --help
```

### Creating a Project

```bash
# Create a new iggy project
cargo run -p iguana -- new ./my-parser
```

### Generating a Parser

```bash
# Generate a parser from an iggy grammar file
cargo run -p iguana -- generate --grammar path/to/grammar.iggy --output ./my-parser
```

## Bootstrapping

The iggy grammar syntax is defined in `iggy/iggy.iggy`. The iggy parser is generated by iguana from this file (self-hosting).

After modifying the grammar definition or generator code, regenerate the iggy parser:

```bash
cargo xtask bootstrap
```

Always bootstrap twice to verify stability: the second run should produce identical output.

## Running a Generated Parser

```bash
# Parse a file
cargo run -p iggy -- --start Grammar path/to/file.iggy

# List available nonterminals
cargo run -p iggy -- --list-nonterminals

# Generate an SPPF visualization (SVG, rendered with graphviz)
cargo run -p iggy -- --start Grammar file.iggy --write-sppf sppf.svg --format svg
```

## LSP Server

```bash
cargo install --path iguana-lsp
```

This installs the `iguana-lsp` binary to `~/.cargo/bin/`. The VS Code extension under `editors/vscode/` launches it automatically.

## WebAssembly

`iguana generate --wasm` builds a generated parser to WebAssembly so it can parse in the browser. It writes a self-contained bundle into `webview/`: a parser lib, a `wasm-bindgen` wrapper crate under `wasm/`, a `manifest.json`, and the web viewer, compiling the wrapper with `wasm-pack` (`--target web --out-name parser`) to produce the wasm module and JavaScript glue. The location is fixed, so `--wasm` conflicts with `-o`. It probes for `wasm-pack` and the `wasm32-unknown-unknown` target, so install them first:

```bash
cargo install wasm-pack
rustup target add wasm32-unknown-unknown
```

The bundle's `iguana-runtime` dependency defaults to a git dependency. To build against a local checkout instead, pass `--runtime-path <dir>`; the generated crate then depends on the runtime by path. This is useful for developing the runtime alongside a grammar, or pinning the bundle to a specific local checkout.

`iguana try` serves the `webview/` bundle over HTTP (a wasm module loads over HTTP, not `file://`), printing a link to open. The location is fixed, so it takes no directory.

```bash
iguana generate --wasm -g mygrammar.iggy
iguana try
```

`iguana try` errors with a build hint if the bundle was not built yet. The viewer it serves is embedded in every `iguana` binary; it is small (~100 KB) because the editor and graph libraries load from a CDN at runtime rather than being bundled.

To exercise the build pipeline on a real grammar during development:

```bash
cargo xtask wasm
```

This generates the iggy bundle into `target/wasm/iggy` and builds it with `wasm-pack`, an end-to-end check of the wasm pipeline.

## Testing

Iguana has two kinds of tests:

- Unit and integration tests inside the crates, run with `cargo test` (or `cargo nextest`).
- Grammar tests under `tests/<name>/`, which check a generated parser's output against golden s-expression files.

```bash
cargo xtask test          # Run the cargo tests, then every grammar's golden tests
cargo xtask test --regen  # Rewrite the grammar goldens instead of checking them
```

`cargo xtask test` runs `cargo nextest run --workspace` (or `cargo test --workspace` when nextest is absent), then builds the grammar parser binaries and checks each one. Extra positional args are forwarded to the cargo run; the grammar tests always run in full and finish in a few seconds.

### Grammar Tests

A grammar test lives in `tests/<name>/`: the `.iggy` grammar, a generated parser crate under `src/`, and test cases grouped into one directory per start nonterminal. Each case pairs a `<name>.txt` input with a `<name>.sexpr` expected output; a case that must fail to parse stores its `Parse error at line N, col M: ...` message as the golden. The check runs the grammar's binary in `--check-sexpr` mode with the truthful render (layout, empty nodes, and EBNF wrappers shown), and `cargo xtask test --regen` rewrites the goldens after an intentional grammar change.

See [docs/testing.md](docs/testing.md) for the layout in detail and the add, regenerate, and remove workflow.

## Development

### Setup

After cloning, run once:

```bash
./setup.sh
```

This checks the rust toolchain, installs `cargo-nextest`, installs the web viewer's Node dependencies when npm is present, flags missing system dependencies (graphviz), and points git at the tracked `.githooks/` directory. The pre-commit hook runs `cargo fmt --check --all` and rejects unformatted commits. The commit-msg hook rejects commit-message trailers (Co-Authored-By, Signed-off-by) and AI-attribution lines; the same check runs on pull requests in CI.

### Checking and Linting

```bash
cargo check -p iguana-compiler   # Type check
cargo clippy -p iguana-compiler  # Lint
```

### After Modifying Generator Code

1. `cargo check -p iguana-compiler && cargo clippy -p iguana-compiler`: fix errors and warnings
2. `cargo xtask bootstrap`: regenerate the iggy parser
3. `cargo xtask bootstrap`: run again to verify stability
4. `cargo xtask test-gen-all`: regenerate all test parsers
5. `cargo xtask test`: run all tests
