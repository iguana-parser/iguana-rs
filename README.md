# Iguana

A GLL parser generator written in Rust.

## Project Structure

```
iguana-rs/
├── iguana/              # Parser generator + CLI
├── iguana-runtime/      # Runtime library for generated parsers
├── iggy/                # Generated parser for iggy grammar syntax
├── iguana-lsp/          # Language server for iggy grammars
├── terrarium/           # Grammar debugging tool (Tauri app)
├── parse-view/          # Shared parse-view renderer (npm package)
├── web-viewer/          # Static web viewer for a wasm-compiled parser
├── editors/vscode/      # VS Code extension
└── tests/               # Grammar test crates
```

### Crates

| Crate | Description |
|-------|-------------|
| `iguana` | Parser generator CLI. Takes a grammar and generates a parser. |
| `iguana-runtime` | Runtime library that generated parsers link against. |
| `iggy` | Parser for the iggy grammar syntax, itself generated by iguana. |
| `iguana-lsp` | Language server providing semantic highlighting and diagnostics for `.iggy` files. |
| `terrarium` | Grammar debugging tool (Tauri app, separate workspace at `terrarium/src-tauri`). |

### Web packages

The repository root is also an npm workspace. Two TypeScript/Svelte packages render a parse tree in the browser, and Terrarium reuses one of them so there is a single renderer to maintain.

| Package | Description |
|---------|-------------|
| `parse-view` | The shared parse-view renderer: a Svelte component with tree, graph, and s-expression views over a parse tree, driven by a pluggable parser backend. Terrarium and the web viewer both import it. |
| `web-viewer` | A static web app that loads a wasm-compiled parser, parses input in the browser, and mounts `parse-view` to render the result. No server and no Tauri. |

### Dependency Graph

```
iguana-runtime  (standalone - no internal deps)
       ^
     iggy  (depends on runtime)
       ^
    iguana  (depends on runtime + iggy)
       ^
  iguana-lsp / terrarium  (depend on all of the above)
```

On the JavaScript side, `terrarium` and `web-viewer` both depend on `parse-view`; `web-viewer` additionally drives a wasm module that `iguana generate --wasm` produces.

## Building

```bash
cargo build              # Build all crates
cargo build -p iguana    # Build just the generator
```

## CLI

To see all available commands:

```bash
cargo run -p iguana -- --help
```

### Creating a Project

```bash
# Initialize a new iggy project
cargo run -p iguana -- init --output ./my-parser --name mygrammar
```

### Generating a Parser

```bash
# Generate a parser from an iggy grammar file
cargo run -p iguana -- generate --grammar path/to/grammar.iggy --output ./my-parser
```

## Bootstrapping

The iggy grammar syntax is defined in `iggy/iggy.iggy`. The iggy parser is generated by iguana from this file (self-hosting).

After modifying the grammar definition or generator code, regenerate the iggy parser:

```bash
cargo xtask bootstrap
```

Always bootstrap twice to verify stability: the second run should produce identical output.

## Running a Generated Parser

```bash
# Parse a file
cargo run -p iggy -- --nonterminal Grammar path/to/file.iggy

# List available nonterminals
cargo run -p iggy -- --list-nonterminals

# Generate SPPF visualization
cargo run -p iggy -- --nonterminal Grammar file.iggy --vis sppf
```

## LSP Server

```bash
cargo install --path iguana-lsp
```

This installs the `iguana-lsp` binary to `~/.cargo/bin/`. The VS Code extension under `editors/vscode/` launches it automatically.


## WebAssembly

`iguana generate --wasm` emits a bundle that runs a generated parser in the browser: a standalone parser lib, a `wasm-bindgen` wrapper crate under `wasm/`, and a `manifest.json`. Build the wrapper with `wasm-pack` to produce the wasm module and JavaScript glue.

```bash
cargo xtask wasm
```

This generates the iggy bundle into `target/wasm/iggy` and builds it with `wasm-pack` (requires `cargo install wasm-pack` and the `wasm32-unknown-unknown` target), an end-to-end check of the wasm pipeline on a real grammar.

## Testing

```bash
cargo xtask test                        # Run the full workspace test suite
cargo xtask test mygrammar::            # Run one grammar's tests
cargo xtask test mygrammar::test_lit    # Run one test
cargo test -p iguana                    # Run iguana's own unit tests
```

`cargo xtask test` uses `cargo-nextest` if installed (faster on macOS) and falls back to `cargo test --workspace` otherwise. Extra positional args are forwarded as test-name filters.

### Grammar Tests

Grammar tests live in `tests/<name>/`. Each is a workspace member crate that owns a grammar and a generated parser library; the test cases (`tests.rs`) are pulled into a single integration-test binary at the workspace root, so the workspace produces one grammar-test binary, not one per grammar.

### Test Commands

```bash
cargo xtask --help                # Show xtask subcommands
cargo xtask test-new <name>       # Scaffold a new grammar test
cargo xtask test-gen <name>       # Regenerate parser after grammar edits
cargo xtask test-gen-all          # Regenerate all test parsers
cargo xtask test-rm <name>        # Remove a grammar test
```

### Creating a Test

```bash
# Scaffold a new grammar test
cargo xtask test-new mygrammar

# Edit the grammar
# tests/mygrammar/mygrammar.iggy

# Edit the tests
# tests/mygrammar/tests.rs

# Regenerate the parser after grammar changes
cargo xtask test-gen mygrammar

# Create/update golden parse tree files
REGENERATE=1 cargo xtask test mygrammar::

# Run the tests
cargo xtask test mygrammar::
```

### Test Structure

```
tests/mygrammar/
├── mygrammar.iggy     # Grammar definition
├── tests.rs           # Test cases (pulled into the unified runner)
├── parse_trees/       # Golden files (auto-generated)
├── Cargo.toml         # Minimal: lib-only, test = false, no [[bin]]
└── src/               # Generated parser library (regenerated by `test-gen`)
```

### Writing Tests

```rust
use mygrammar::{parse_program, parse_tree::to_sexpr};
use iguana_runtime::input::Input;
use iguana_runtime::parse_tree::ParseContext;
use iguana_runtime::testing::{check_golden_file, golden_path};

const GRAMMAR_DIR: &str = concat!(env!("CARGO_MANIFEST_DIR"), "/tests/mygrammar");

fn check(input: &str, test_name: &str) {
    let input = Input::from(input);
    let ctx = ParseContext::new();
    let result = parse_program(&input, &ctx).expect("Parse failed");
    let actual = to_sexpr(result.tree.as_parse_tree());
    check_golden_file(&actual, &golden_path(GRAMMAR_DIR, test_name));
}

#[test]
fn test_example() {
    check("input text", "example");
}
```

Run with `REGENERATE=1` to create or update golden files. See [docs/testing.md](docs/testing.md) for the full grammar-test workflow.

## Development

### Setup

After cloning, run once:

```bash
./setup.sh
```

This checks the rust toolchain, installs `cargo-nextest`, flags missing system dependencies (graphviz), and points git at the tracked `.githooks/` directory. The pre-commit hook runs `cargo fmt --check --all` and rejects unformatted commits.

### Checking and Linting

```bash
cargo check -p iguana          # Type check
cargo clippy -p iguana         # Lint
```

### After Modifying Generator Code

1. `cargo check -p iguana && cargo clippy -p iguana` -- fix errors and warnings
2. `cargo xtask bootstrap` -- regenerate iggy parser
3. `cargo xtask bootstrap` -- bootstrap again to verify stability
4. `cargo xtask test-gen-all` -- regenerate all test parsers
5. `cargo xtask test` -- run all tests
