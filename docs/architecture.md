# Architecture

Iguana is a data-dependent GLL parser generator. The generator (`iguana`) takes an iggy grammar and emits a self-contained Rust crate. Generated parsers link against `iguana-runtime`, which provides the GLL machinery shared by every output.

## Crates

| Crate | Role |
|-------|------|
| `iguana-runtime` | Runtime library shared by every generated parser. No internal dependencies. |
| `iggy` | Parser for the iggy grammar syntax, generated by iguana from `iggy/iggy.iggy`. |
| `iguana` | Parser generator and CLI. Reads an iggy grammar via `iggy`, emits a parser crate. |
| `iguana-lsp` | Language server for iggy grammars. |
| `terrarium` | Tauri-based grammar debugging tool. Separate workspace at `terrarium/src-tauri`. |
| `editors/vscode` | VS Code extension. Launches `iguana-lsp`. |
| `xtask` | Build and workflow tasks. |
| `tests/<name>` | One workspace member per grammar test. |

## Dependency graph

```
iguana-runtime  (no internal deps)
       ▲
     iggy   (depends on runtime)
       ▲
    iguana  (depends on runtime + iggy)
       ▲
  iguana-lsp / terrarium  (depend on the above)
```

The relationship between `iguana` and `iggy` is circular at the source level: iguana parses iggy grammar files using `iggy`, and `iggy` itself was generated by an earlier build of iguana. The `bootstrap` xtask keeps the committed iggy parser in sync with `iggy/iggy.iggy`. See [development.md](development.md#bootstrapping).

## Generation pipeline

The generator turns a `.iggy` file into a parser crate. The pipeline lives in `iguana/src/generator/` and produces:

```
src/grammar_data.rs    static tables: terminals, nonterminals, slots, first/follow/prediction sets
src/parser.rs          parse functions, one per nonterminal
src/parse_tree.rs      parse tree types and the tree builder
src/scanner.rs         scanner (when @regex tokens are used)
src/types.rs           shared types across modules
src/lib.rs             public API and re-exports
src/main.rs            CLI binary for the generated parser
Cargo.toml             scaffolded once, hand-maintained after
```

Each output file is produced by a dedicated `*_gen.rs` module. After generation, `post_process.rs` rewrites `#[comment = "..."]` into `//` and `#[doc = "..."]` into `///`, and inserts blank lines before item-level definitions for readability.

## Runtime

`iguana-runtime` hosts the parsing infrastructure: descriptors (work items in the GLL worklist), the graph-structured stack (GSS), the shared packed parse forest (SPPF), input handling, and the parse-tree builder. The runtime is performance-critical; allocations and trait dispatch on hot paths need justification.

## Tooling

`iguana-lsp` and `terrarium` share a set of stateless analysis functions for highlighting, formatting, symbols, and diagnostics. The LSP server wraps them in protocol handlers; terrarium calls them directly through Tauri commands. Terrarium also runs generated parsers as subprocesses (not as library calls) and communicates with them through CLI flags and JSON temp files.
